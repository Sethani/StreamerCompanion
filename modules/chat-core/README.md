# Live Chatbox

Live chat ingestion, moderation, pronouns and PluralMind without the deferred SQLite archive or the personal server. The chat renderer preserves the existing Izzy stream-chat design and first-party enrichment changes. First-party code is Sethani/MIT; upstream stream-chat (Izzy, MIT) and PluralMind 2.1.1 (leahinmoonlight, MIT) notices are included in third-party/.

Install through the catalogue and start Live Chatbox. No Streamer.bot action import is required. Default service port is **3136**, separate from the old Chat Archive on 3129 so it can remain open during testing. Streamer.bot must expose a local unauthenticated WebSocket (default ws://127.0.0.1:8080/). Twitch and YouTube messages/moderation are subscribed once per connection, with reconnect/heartbeat handling. Chat Routing remains a separate outgoing-message module.

Open Settings and paste the existing chatbox source URL into Appearance, then save. Only known appearance/filter options are retained; credentials, connection URLs and CDN/script settings are discarded. Platform/enrichment switches have a separate explicit import button. No live OBS setting is changed by the module. Test messages are synthetic, appear in all connected renderers, and never post to chat or query a real user's profile.

After a controlled visual check, replace only the URL of the **existing Chatbox OBS browser source** with http://127.0.0.1:3136/chat/chat.html . Keep its dimensions, placement and filters. Saved appearance applies by default; explicit appearance query parameters override it. This existing chat source stays separate from the combined feature overlay; the module does not register itself for automatic aggregate embedding. No additional OBS source is needed. Refresh the chat source after changing appearance. Enable/disable and moderation apply live.

The stream-chat CSS/layout is retained, including bubbles, colors, font preferences, direction, timestamps, badges, emotes, announcements and filters. Open Sans continues to load from Google Fonts when available; system fallback is used offline, and no font binaries are bundled. Twitch/YouTube badge/emote URLs remain remote resources, not redistributed image files. Browser version warnings/debug traffic and direct chat WebSockets are disabled: the service owns one feed. An outage leaves the live picture transparent without operational diagnostics; Settings shows connection status.

Pronoun and PluralMind lookups use bounded in-memory caches, concurrency and timeouts. Raw messages are delivered immediately and updated asynchronously; failed lookups leave ordinary messages usable. Message IDs/deduplication and deletion guards are bounded in memory. Deletions, timeouts/bans and chat clears cancel pending updates; no message replay is provided on reconnect. The renderer uses a default maximum of 200 messages when no legacy limit was set, with existing off-screen/fade cleanup retained.

Only configuration is persisted. The module never opens, migrates, deletes or packages the old archive database. No viewer history, profile cache, incoming message text or synthetic test state is written to disk or service logs. Existing archive data/automatic-start preferences remain untouched; the new service has its own host-managed automatic-start choice. Stop its own automatic-start separately when rolling back. Rollback: restore the previous Chatbox URL and restart the old Chat Core/archive if needed. Retiring the personal server still requires the other vital feature migrations.
