# Bouncing Avatar extraction

## Pass 1 - local package and combined-overlay acceptance

November 14, 2026. Bouncing Avatar 1.0.0 is an **unpublished local candidate**. Production renderer, private image, OBS sources, routing, services and installed packages remain unchanged. Whole-system status stays **22/24** until backed-up handoff and acceptance. Do not install this beside an active legacy renderer without the next cutover pass.

Package ID `bouncing-avatar`, UI/routing ID `bouncing`, Sethani/MIT. It targets Companion >=1.3.1 with Universal Dock, Universal Overlay and Source Modules, and an independent loopback service on 3144. There are no native imports/actions, OBS connection, personal defaults or app/Phone Deck rebuild. Universal Overlay discovers its existing `extensionOverlayUrl`; no additional OBS source is required. Source Modules retains the exact `bouncing` key and saved scene lists. The optional Phone Deck contribution is read-only setup status; existing Source Modules phone controls can change visibility modes without replacing the scene list.

The private combined renderer was traced at `public/obs/source.js` (bouncing state and animateBouncing), `source.css` (bouncing-layer/avatar), and `source.html` (image). It uses a fixed 220 px width, natural image aspect ratio, 220 px/second on each axis, centred startup, a 50 ms delta clamp, reflected wall collisions, one 47-degree hue step per bounced frame, white 18 px drop-shadow and a transparent viewport. The standalone `public/bouncing/index.html` has a different responsive width; the candidate deliberately copies the combined stream renderer. Production source usage still needs a fresh live inventory before cutover.

Copied motion lives in `service/public/motion.js`; CSS preserves the fixed combined size/glow/transparency. The only motion edge correction is avoiding repeated colour flashes on an axis with zero available travel. Resizing clamps to the viewport. Missing/failed images never start animation. Ordinary Universal Overlay scene gating unloads the iframe and a later new frame starts centred; polling within the same visible frame never reloads the image or restarts its motion. This uses existing ordinary-module lifetime rules rather than the external-widget ownership protocol.

Settings provide Enable, image selection, optional colour-on-bounce and Save. The image library is folded initially. Disabling colour changes returns to original image colours. New installs are disabled with no image. Uploads select a draft only; the previous image stays live until Save. PNG/JPEG/GIF/WebP uploads are private and content-addressed; limits are 8 MiB, 8192 pixels/side, 32 million pixels, 64 images. SVG, remote URLs and filesystem paths are rejected. Header dimensions bound decoding; the browser ultimately decodes the raster and stays transparent if it fails. WebP header handling follows [the primary container specification](https://developers.google.com/speed/webp/docs/riff_container). Personal artwork is not redistributed.

Configuration and the image index use one revisioned atomic private record; image bytes are written before the index, with rollback if index persistence fails. Concurrent saves/uploads/deletions serialize; stale revisions fail without overwriting data. Duplicate uploads reuse the same blob. Deleting the currently saved image is blocked. Unreferenced leftovers are not served. Invalid saved records fail closed without replacing them. Settings polling preserves drafts/focus/selection/scroll and reports conflicts; mutations are never retried automatically.

All requests enforce exact loopback Host/port. Private APIs/media additionally require same-origin requests and reject cross-site requests; writes require Origin plus CSRF. No CORS or installation bearer token is exposed. Only the public shell assets permit cross-site embedding, allowing Companion/OBS file documents to embed the local settings/renderer; child API calls remain same-origin. Settings use a constrained CSP. Health/Phone Deck expose booleans only, with no file names, images, credentials or private paths. Renderer failures show no audience diagnostics. The service makes no OBS, native, Twitch or external network requests.
