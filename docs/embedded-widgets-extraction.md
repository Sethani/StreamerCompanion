## Preservation issue to resolve before implementation

The old combined renderer keeps its iframe loaded when routing hides a layer using CSS. Its first load is lazy: an initially disallowed Tangia layer is not loaded until allowed. Explicitly disabling a widget or clearing its URL unloads it. Repeated polling keeps the same frame; geometry changes do not recreate it.

The modern Universal Overlay removes outer module frames when their scene rule does not match. Simply registering Tangia as a normal routed module would therefore restart its external application on scene transitions. The legacy generic renderer also skips disabled-group rendering rather than clearing already loaded children. Preserve these semantics deliberately; do not copy incidental stale-data bugs as a contract.

Recommended implementation: investigate a narrowly scoped, opt-in persistent-frame policy in Universal Overlay for external widget owners. It must load only after the first eligible scene, retain a hidden frame across ordinary scene exclusion, and unload on owner removal/unavailability, lost routing connection, explicit disable/URL clear or shutdown as defined by the verified contract. Avoid changing other modules' iframe lifecycle. Legacy and modern combined renderers must agree on ownership before either starts an external embed. Add tests for hidden frames receiving no duplicate navigations/audio starts, and document the distinction between hiding and disabling. If this cannot be made safe within the current module contracts, stop at a local candidate and record the required contract change before publication.
