# OBS request traffic follow-up

Recorded November 14, 2026 during the accepted Widgets handoff.

The private cutover verifier repeatedly enumerated inputs, mute states and track masks and opened a fresh connection for each CLI phase. Those finite verification bursts stopped. Its replacement visibility/stability check held one OBS socket, made four total requests and then observed the widget owner without OBS polling. A further 65.7-second check made zero OBS requests. Temporary observers closed afterwards.

The remaining OBS clients were the repository server, Phone Deck and Streamer.bot. Phone Deck already holds a persistent WebSocket. In `modules/phone-deck/service/runtime.js`, the two-second timer calls `obs.refresh()`. In `service/obs-client.js`, every OBS event also schedules a refresh. Core refresh reads scene/stream/record/input inventories and per-input mute state. Holding the connection open therefore does not remove its periodic request volume.

Phone Deck 2.0.4 implements the follow-up. The two-second runtime tick now reconciles only when due: status reads have a five-second minimum interval (normally six seconds at that tick cadence), and full inventories have a thirty-second minimum interval. One OBS socket is retained. Program/preview scenes, outputs, pause, mute, volume, scene-item visibility and transition events update state directly. Unrelated events cause no requests. Structural events coalesce over 80 ms; item changes read item inventories, scene changes read scenes/items, and input changes read inputs/mutes/volumes/items. Capability reads are cached for partial reconciliation, and Studio Mode is read once per snapshot.

Full bootstrap, manual refresh and button dispatch still read fresh state. Existing exact-target checks, bounded readback, unsupported-feature isolation, durable outcomes and no automatic mutation retry remain. Collection changes clear stale targets and invalidate in-flight reads. Event sequence tracking preserves newer state events over delayed snapshot responses; reconnect generations fence old connection results. Repeated structural changes requeue invalidated scopes rather than dropping work. Reconciliation repairs missed events without applying any settings or starting outputs.

`companion/scripts/test-phone-deck-obs-traffic.js` exercises 102 audio inputs, actual runtime ticks, bounded health reads, hundreds of status/unrelated events without requests, scoped/coalesced inventories, missing-event repair, delayed snapshot/event ordering, overlapping structural changes, collection fencing and mutation-free reconnect. The browser volume fixture now sends the actual InputVolumeChanged event instead of relying on a scene event to trigger a full scan. Its save steps also wait for the preceding client response before the next save. Publication and production adoption evidence follows below after the gates complete.

Future operational checks should reuse a single temporary connection, collect a baseline once, and verify relevant changes rather than repeatedly enumerating all audio/input state. No hidden production-profile Companion instance is needed.
