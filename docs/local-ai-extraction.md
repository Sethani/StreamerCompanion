# Local AI / Ollama extraction

## Implementation and handoff scope - November 14, 2026

Local AI 1.0.0 copies the used raid/shoutout text functionality into an independent service on **3145**, targeting Companion >=1.3.1. Production handoff is not complete until the two private callers and legacy ownership guard have been adopted and verified. The feature checklist stays **23/24** until then. No new overlay, native module import, app rebuild, model download or Ollama executable is shipped.

The audit found two active callers: the existing raid action and Owned Video Clip Shoutouts. Each has one HTTP endpoint literal under the old `/api/warmgeneration/raid` or `/shoutout` route. The proposed private change replaces only those URLs; action IDs, triggers, queues, lookup/authentication, official-shoutout conditions, clip dispatch, chat routing, timing and session bookkeeping stay with their existing native owners. Writing Challenge's classifier is parked and excluded. The shared legacy state engine's Ollama backend label is metadata rather than another inference caller.

The old Node server also warms the model at startup. The staged private ownership marker blocks that warm call and retires both old generation routes without proxying or falling back. The unused Writing classifier remains outside this slice. Ollama daemon startup currently belongs to the existing private application launcher; the new package never launches the daemon or installs weights. The final old-server-off/startup rehearsal must preserve daemon startup while retiring the legacy server launch and overlay root separately.

## Preserved text behavior

First-party helpers are copied into `service/text.js`: the same compact 450-character message builder, 90-character flavour prompts, fallback skeletons, explicit-pronoun formatting, placeholder rejection, first-person/disallowed wording checks, category/clip separation and raid/broadcaster-context protection. Validation remains the legacy behavior, not a new semantic moderation guarantee. A private synthetic parity check compares 37 prompt/fallback/validator cases with the original functions. No channel identifiers, prompts, messages or viewer history are copied into public defaults or saved by the service.

Only a flavour phrase comes from Ollama. It never sends chat, plays a clip, invokes Twitch or rewrites viewer state. Missing context, disabled AI, model/API errors, malformed output, timeout, redirect, oversize response and inference overflow return deterministic fallback text. Configuration changes cancel old HTTP requests and discard obsolete model results; failed persistence leaves existing requests/settings intact. Generation is not automatically retried. Two inference requests may run concurrently; explicit warming is single-flight. Origin-less native JSON requests get plain text with the existing body shape and routes at the new port.

The backend uses the documented [non-streaming generate API](https://docs.ollama.com/api/generate), preserving `model`, `prompt`, `stream:false` and `keep_alive`. Checking installed models uses [GET /api/tags](https://docs.ollama.com/api/tags). URL/model/timeout/keep-alive and optional startup warming are private settings. Fresh installs are disabled with no model; existing installed models must be selected explicitly. Checking/reconnection/status never loads a model. Startup warm is opt-in and runs once per service startup, not on reconnect or Save.

## Boundaries and security

The URL accepts loopback HTTP only, with no credentials/path/query/fragment; redirects are rejected. Request/response bodies and fact complexity are bounded. Native generation rejects Origin and browser Fetch headers, accepts JSON only and never offers an arbitrary prompt/model/URL proxy. Settings, sample previews and explicit warm/check operations are separate same-origin/CSRF routes; saves use atomic revision checks. Exact Host/port and no CORS protect private data. File-based Companion/OBS documents may embed only the public shell assets; the child reads its own same-origin API. The sample preview uses synthetic facts only.

Health reports module readiness independently of Ollama reachability; an unavailable optional backend is not a missing module dependency. Read-only Phone Deck status projects enabled/configured/backend-available/warming, without model/address/prompt/message data. No card is added automatically. No hard dependency on Phone Deck or Shoutout Clips is introduced. Configuration corruption fails closed; upgrades/reinstall preserve private configuration/favorites/automatic-start. Models/software remain independently installed, with their own distribution terms.

## Release and off-stream handoff gates

1. Record exact source/archive and pass Windows/Linux CI. Publish only Local AI, then validate the actual released archive and preserved private data in packaged Companion 1.3.1.
2. Re-read live OBS stream/record state. Snapshot the two caller actions, native globals/database, current scene/audio/source state, private Ollama settings, existing services/preferences/pairing and repository server. Keep all sensitive values in ignored private backups.
3. Install/configure the new service while disabled. Preserve the existing model, URL, timeout and keep-alive; use explicit startup-warm preference. Start it through the existing Companion, check the installed model and use synthetic preview facts without chat or raids.
4. Before closing Streamer.bot, identify/suspend only its exact shutdown watcher so the broad old stop script cannot close unrelated applications. Close Streamer.bot normally; back up its final flushed data; replace only the two endpoint literals and preserve all other records.
5. Adopt the tested legacy server guard/marker and restart only the verified repository Node server, using its exact executable/script/PID and server-only lifecycle. Keep Phone Deck HTTPS, OBS, Companion, Ollama and other services running. Restart Streamer.bot from its current profile and retain its usual launcher/watcher behavior.
6. Verify new endpoints, deterministic failure behavior, unchanged model/settings and clip/chat orchestration, native import/compile/connection readiness and incoming Twitch after restart. Record tested versus unchecked live effects. Old generation routes must not fall back. Keep rollback available: disable modern AI, restore original caller actions/server and matching marker state off-stream, preserve all private settings/identities.
7. Only after handoff verification mark 24/24 feature areas implemented. Existing Widgets owner recovery and whole-system cold-start/old-server-off rehearsal, source/startup adoption and final legacy Import settings cleanup remain separate. Do not repeat accepted Avatar/Cameras/Reactive/Tangia tests.
